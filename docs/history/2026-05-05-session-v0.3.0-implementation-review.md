# 2026-05-05 - v0.3.0 Implementation Review

## Summary

The user asked for an independent review of the v0.3.0 implementation,
then a critical perspective from QA and SRE engineers, then asked that
all findings be documented and the chat history recorded. Build,
`go vet`, and `go test ./...` all pass clean on `release/v0.3.0`.

## Process

1. Spawned four parallel read-only `Explore` subagents to audit the
   storage, protocol, BFF runtime, and harness surface tracks against
   their v0.3.0 design docs. Each returned a conformance table, concern
   list, and verdict.
2. Spawned two more parallel `Explore` subagents framed as adversarial
   QA and on-call SRE. They were given the prior findings as context to
   avoid retreading and instructed to find what would break under
   real-world use.
3. Verified every load-bearing claim against the actual code before
   accepting it. Discounted three subagent claims that did not hold up.

## Findings recorded

Comprehensive findings doc written at
`docs/releases/v0.3.0/.reviews/v0.3.0-implementation-review.md`. It is
structured as:

- Verdict: ship-with-followups
- What is solid: storage, protocol, detached transcript invariant,
  `AppendRunEvent` transactional correctness, `run.permissions` wiring
- Critical findings (C1–C4): swallowed relay errors, no-op heartbeat,
  dead `Stuck`/`StuckSeconds` protocol, unbounded registry maps
- High findings (H1–H6): non-transactional `turn.submit` pre-dispatch,
  un-emitted inactive stages, no run-events retention, one-way schema
  migration, missing structured logs/metrics, attach-lease TOCTOU
- Medium findings (M1–M6): untested state transitions, missing
  idempotency test, no end-to-end harness command tests, thin protocol
  fixtures, untested `LinkTurnToRun` constraint, fidelity not enforced
  in replay
- Discounted claims: concurrent `AppendRunEvent` is safe (verified
  transactional); `UNIQUE(turn_id)` already prevents duplicate
  turn-to-run links; `ProtocolVersion` unchanged; quantitative load
  estimates are illustrative only
- Recommendations: top five items to land before a v0.3.0 tag
