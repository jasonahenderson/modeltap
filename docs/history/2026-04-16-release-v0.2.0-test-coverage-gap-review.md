# 2026-04-16 — v0.2.0 Test Coverage Gap Review

## Context

Before starting implementation of v0.2.0 (FEAT-0008 BFF server + FEAT-0009 terminal harness), made a final pass over the plan and track files to assess whether test coverage was comprehensive enough to ship.

Prior to this review the plan had 54 work units (WU-039–WU-092) with tests embedded in each WU's definition of done, plus:
- WU-067 — per-track integration tests for Track A (BFF)
- WU-087 — per-track integration tests for Track B (harness) against a mock server
- WU-088 — cross-stack E2E (real harness ↔ real BFF ↔ mock provider)

## Gaps Identified

### Gap 1 — Protocol contract drift between parallel tracks
FEAT-0008 §"Interface Definition" explicitly calls for "a standalone interface definition ... to enable automated contract testing." The round-trip tests in WU-039/040/041 only catch *self-consistency* inside Track 0. With Tracks A and B built in parallel, silent drift in protocol field shape surfaces only at WU-088 — too late.

### Gap 2 — Dedicated security review pass
`docs/agents.md` defines a Security Reviewer role and makes a security pass a precondition for "done", but no WU materialized this for v0.2.0. Shipping 13 harness-local tools (Bash, Git, Write, Edit, Read with magic-byte sniffing, WebFetch, etc.) plus a new BFF transport, session-lock mechanism, and credential-bearing provider config without an explicit security WU is unacceptable risk.

### Gap 3 — Performance budgets and benchmarks
FEAT-0008 claims "zero added latency" for streaming; FEAT-0009 implies interactive TUI responsiveness. No WU establishes concrete budgets or adds benchmarks. Without budgets, regressions slip in invisibly and "feels slow" becomes the only signal.

### Gap 4 — Real-world storage migration (v1 → v2) not tested
WU-045 DoD covers *creating* the v2 schema on a fresh DB. It does not cover *upgrading an existing v1 database* with live capture data, metrics state, and retention state. A bricked user DB on upgrade is a worst-case v0.2.0 failure mode.

## Decision

User selected Option 1: add all four proposed WUs.

### Critical path impact
None of the new WUs extend the critical path:
- WU-093 parallelizes with WU-042-045; it becomes a prerequisite for WU-067 and WU-087 (integration suites), not for Track A/B foundation WUs.
- WU-096 parallelizes with WU-043/044 and any Track A WU after WU-045.
- WU-094 and WU-095 parallelize with WU-088/089 in the integration track.
