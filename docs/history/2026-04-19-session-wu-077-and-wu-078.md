### WU-077 — Write and Edit tools (`797f278`)

`internal/harness/tools/write.go` + `edit.go` (+ tests). Both
tools register at `RiskWrite`. Combined WU commit (tests +
implementation in one) matching the recent style (WU-073 through
WU-075).

**WriteTool**
- Input: `file_path` (absolute or project-relative), `content`.
- Resolves paths with `filepath.Rel` against the project root;
  rejects `..`-escapes and absolute paths outside root.
- `os.MkdirAll` on the parent before `os.WriteFile` — callers don't
  need to pre-create directories.
- Snapshots existing contents before overwriting and inlines them
  into the tool output (design D7 — no separate snapshot file).
- Marks the file in the `FileTracker` so Edit can modify it
  without a separate `Read`.

**EditTool**
- Input: `file_path`, `old_string`, `new_string`, optional
  `replace_all`.
- Enforces the Read-before-mutate contract via
  `FileTracker.HasRead` — errors if the file wasn't Read (or
  Written) earlier in the session.
- `strings.Count` check: 0 matches → "not found"; >1 without
  `replace_all` → "not unique (N occurrences)"; else
  `strings.Replace` / `strings.ReplaceAll`.
- Output includes the path, replacement count, and a 2-line diff
  truncated at 200 chars per side so the transcript stays readable
  when editing large blobs.

Shared `resolveInRoot` helper lives in `write.go` and is reused by
`edit.go` (and available for WU-078/079 if needed).

Tests cover: Write new / overwrite-with-snapshot / create-dirs /
outside-root-rejected / missing-fields / relative-path-resolution;
Edit single / replace-all / no-match / ambiguous / requires-read /
diff-output / missing-file / outside-root / missing-fields. All
race-clean.

### WU-078 — Bash and Git tools (`96ec3b7`)

`internal/harness/tools/bash.go` + `git.go` (+ tests). Both tools
register statically at `RiskExecute`; input-dependent escalation /
de-escalation happens at the permission layer.

**BashTool**
- Input: `command`, optional `timeout_ms` (capped at 600000),
  optional `description` for the approval prompt.
- `exec.Command("sh", "-c", command)`, `cmd.Dir = projectRoot`,
  context-bound timeout (default 120s).
- Combined stdout/stderr capture; truncates at 100KB to the
  trailing half with a `[output truncated — showing last N bytes
  of M]` marker.
- Returns StatusError with `exit N` on non-zero exit,
  StatusError with `timed out after D` when the context deadline
  fires (before the fix: would have surfaced as a generic kill).

**GitTool**
- Input: `command` — git subcommand + args without the leading
  `git` (e.g. `status`, `log --oneline -n 5`).
- `exec.Command("sh", "-c", "git "+command)` with the same
  truncation / timeout discipline as Bash (60s default).
- `ClassifyGit(command) RiskLevel` — in-tool helper returning the
  per-invocation risk level. Precedence:
  `destructive > mutation > read-only > execute default`,
  mirroring the design D3.2 matrix rows.
- `IsGitRead(command)` — boolean shorthand used by the permission
  layer for the RiskExecute fast-path.

**Permission-layer changes**
- `Check()` gained a Git-read fast path in the `RiskExecute` branch
  — `if name == ToolNameGit && IsGitRead(gitCommandFromInput(input))
  → PermAllow`. This downgrades safe reads (`git status`, `git log
  …`) to auto-allow in every permission level including Default,
  matching the design matrix row "Git (read): Allow/Allow/Allow".
- `alwaysPrompt`'s Git branch refactored to use the new
  `gitCommandFromInput` helper so both `args[]` and `command`
  input shapes route through the same extraction. WU-075's
  existing `TestPermissionEnforcer_GitDangerous` (which uses
  `args`) still passes.

## Design deltas taken during implementation

Two deviations from the Bundle 7 design as written, both
conservative:

1. **gitReadCommands narrowed.** Design listed `remote` and
   `config` as read-only. In practice:
   - `git remote add foo https://…` creates a remote (mutation).
   - `git config user.email foo@bar.com` sets a value (mutation).
   Classifying either as read-only via the subcommand alone would
   auto-allow mutations in Default mode. I removed both from the
   read list — first use prompts, and the user can approve once
   per session via the normal first-use flow.

2. **Positional-arg mutation detection** added for `branch` and
   `tag`. Bare `git branch` and `git tag` are reads (they list),
   but `git branch newname` and `git tag v1.0` create. The
   existing `mutationFlags` check handled `-d`/`-m` but missed
   these positional forms. Introduced `positionalMutationSubs`
   — subcommands for which any non-flag positional arg triggers
   `RiskExecute`.

## Dangerous-pattern fix (WU-075 catalog, exposed here)

`dangerous.go` had a latent regex bug that `TestGit_Classification`
surfaced:

```
{Pattern: `\bpush\s+.*\s-f(\s|$)`, Desc: "force push (short flag)"},
```

The `\bpush\s+` prefix consumed the single space between `push`
and `-f` when `-f` was the first argument, leaving nothing for the
inner `\s-f` to match. So `push -f origin main` didn't match even
though `push origin main -f` did. Rewrote to:

```
{Pattern: `\bpush\b.*(^|\s)-f(\s|$)`, Desc: "force push (short flag)"},
```

Now the separator can come from anywhere inside the command, and
`-f` is anchored to either a whitespace or start-of-string on the
left and whitespace-or-end on the right (so `--force` doesn't
falsely match). Paired `--force` pattern tightened to
`\bpush\b.*--force\b` for symmetry.

- **Bash/Git both use `sh -c`**, not `exec.Command("git", args...)`.
  Shell quoting for git args (commit messages, etc.) is hard to get
  right without a dedicated shlex dependency; running via the shell
  matches Bash behaviour and keeps the permission layer as the
  single gate. The cost: command injection is possible through
  git's command string, but so is everything-else through Bash —
  the permission model already accepts that trade.
