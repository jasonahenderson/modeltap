## Suggested approach per failure

**(1) `TestHandleTurnSubmit_HappyPath`** — `expected at least 1 persisted
turn, got 0`. Likely a timing/race issue: the test asserts persistence
before the BFF's async write has flushed. Read `internal/bff/turn.go` and
the test; check whether the test waits on a flush signal or just
polls/sleeps. Fix by waiting on a signal, not a timeout.

**(2) `internal/harness` SIGSEGV** — most concerning, real bug. The panic
happens during package tests but no specific test name is in the log.
Reproduce locally with:

```
go test -race ./internal/harness/...
```

The pc=0x9567a8 + addr=0x18 hints at a method call on a nil pointer —
likely a 24-byte-into-struct field deref. Use `go test -race -run .
./internal/harness/... -v` to surface which test triggers it. Look for
shared state mutated without synchronization, or a goroutine that outlives
the test.

**(3) `TestBash_Timeout`** — process kill not happening quickly enough on
Linux. `bash_test.go:107` expected fast kill but got 10s (the timeout
fired but process kept running until natural exit). On macOS the kill
works; on Linux it doesn't. Likely the bash tool sends SIGTERM but the
spawned process inherits a process group it doesn't kill. Fix: kill the
process group (`-pid`), not just the leader.

**(4) `TestBash_OutputTruncation`** — `output should announce truncation:
"x"` means the assertion saw just `"x"` instead of a truncation marker.
Probably the output didn't actually exceed the truncation threshold on
the CI runner (different env, different output ordering). Read the test
and tool to see what threshold and announcement format are expected.
