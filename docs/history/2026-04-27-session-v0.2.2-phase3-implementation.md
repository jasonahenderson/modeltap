## Major implementation discoveries (Phase 3 design revisions)

Per `.agents/process.md` Prime Directive #4, implementation may
reveal flaws that require explicit design revision. Two surfaced
during Phase 3:

### 1. SubmitTurnSync promise hook was unnecessary

The Phase 1 design proposed adding
`ConnectionManager.SetSubmitPromiseRouter` to bridge `App.Update`'s
`TurnSubmittedMsg`-emitting tea.Cmd back to a synchronous return.
The Phase 2 review accepted this and worked through the
double-delivery problem. During WU-104a implementation it became
clear that `Client.SubmitTurn` is **already synchronous** — the
async-via-tea.Cmd pattern existed only because `App.Update` wrapped
the sync call. With App deleted, the new `ProductionRuntime` calls
`Client.SubmitTurn` directly. No promise router needed; no
double-delivery problem to solve. The Phase 1 + Phase 2 design
complexity was solving a non-existent problem. Recorded in the
WU-104a commit body.

### 2. ViewportState cache pointer wasn't enough — scroll
   preservation itself was broken

WU-107's Phase 2 design said "preallocate a `*ViewportState` cache
in `New()` so `View()` can mutate through it." Implementing the SC3
parity test surfaced that the bug was deeper: the original
`Model.View` did `SetContent` on a **local** viewport copy, so the
persistent `state.transcript` viewport never had content set. Mouse-
wheel scroll was a no-op against the empty viewport, and `AtBottom`
always returned true. SC3 was effectively unimplemented — it had
never been wired correctly. The fix moved the SetContent + followTail
logic into a `state.refresh()` helper called at the end of every
`Model.Update`; `View()` became pure (`return m.state.transcript
.View()`); the `viewportCache` pointer trick was dropped entirely.
The persistent viewport itself is now the cache. Recorded in the
WU-107 commit body.

## Per-WU summary

### WU-107 (`9218a46`) — viewport state + scroll preservation

- Added `ViewportState` value-typed struct + `Model.ViewportState()`
  accessor.
- Refactored `Model.View` / `Model.Update` so `refresh()` applies
  SetContent + followTail to the persistent viewport at the end of
  every Update tick.
- New parity test `TestManualScrollPreservedWhenNotFollowingTail`
  in `viewport_test.go`. Closes the WU-102 SC3 follow-up gap.

### WU-104a (`4c1f527`) — ProductionRuntime + SubmitTurn + BFF stub

- `ProductionRuntime` (~430 lines) wraps the surviving harness
  plumbing: `ConnectionManager`, `ProtocolClient`, `ToolDispatcher`,
  `ContextManager`, plus a new `runtimeState` implementing
  `ModeReader` and a `deferredSender` wrapping
  `atomic.Pointer[tea.Program]`.
- `SubmitTurn` end-to-end: resolves attachments via
  `ContextManager` (file refs) + concatenates paste payloads;
  calls `Client.SubmitTurn` synchronously; returns
  `SubmitAccepted{RunID, Label}`.
- `permissionPromptCallback` scaffolding (sync.Map of channels;
  request ID generation; sender.Send).
- `internal/harnesshost/testutil/bffstub.go`: unix-socket JSON-RPC
  server speaking `capabilities.register`, `turn.submit`,
  `turn.cancel`, `ping`. Layer 3 tests (per Kimi #9).
- Adapter `tokenAttachments` map populated on dispatchSubmit (per
  Codex #3).

### WU-104b (`c2733df`) — LoadPreview + ResolvePermission + InterruptRun

- `LoadPreview` validates path via `ContextManager.Resolve`; runs
  the registered `tools.Read` tool's Execute; translates the
  ToolExecResult into `harnessshell.PreviewPayload`.
- `ResolvePermission` looks up the per-ToolCallID promise channel,
  writes the decision; synthesizes
  `harnessshell.PermissionResolvedEvent` so the adapter's pause
  buffer drains.
- `InterruptRun` calls existing `Client.CancelTurn`; on error or
  no-live-client synthesizes `harnessshell.RunStoppedEvent`
  (per Kimi #7) for clean stop UX.

### WU-104c (`1c97203`) — DispatchCommand + SummarizePaste + MCP

- `DispatchCommand` routes /plan, /build, /auto (mode), /model,
  /models (model.list / model.switch), /session, /sessions
  (session.list / resume / clear / fork), /context (context.list).
  Documented stubs for /compact, /history, /mcp.
- `SummarizePaste` uses `content.transform` with passthrough on
  RPC error.
- Out-of-band sender pattern (per Kimi #3): runtime emits
  `HostStatusEvent` directly via deferredSender for command
  results.

### WU-105 (`890a4a5`) — modeltap shell CLI

- `internal/cli/shell.go` with the new `modeltap shell` command;
  flags `--socket`, `--resume`, `--project`, `--model`.
- `runShell` composes config → ProductionRuntime → Adapter →
  tea.Program with the AttachProgram-before-Start ordering rule
  (per Kimi #6).
- root.go registers the new command; root_test.go updated.

### WU-106 (`6eeb7ad`) — plumbing cleanup

- Deletes the audit's full delete column: app.go, input.go,
  keys.go, markdown.go, viewport.go, statusbar.go, connux.go,
  paste.go, permission_prompt.go, theme/, styles/, plus
  compact.go, history.go, models.go, sessions.go (whose RPC paths
  inlined into DispatchCommand).
- Trims `messages.go` to the audit's enumerated keep list (13
  runtime-event types). Trims `model.go` to ConnStateInfo,
  TokenInfo, and ConnState* constants.
- Connection event-bridge `BannerMsg` sends replaced with
  `StatusUpdateMsg` so the projection layer routes them.
- `tool_dispatcher.go`: AppState.CurrentMode helper removed;
  `runtimeState` in harnesshost satisfies ModeReader directly.
- App-driven integration tests (e2e_harness_bff_provider, etc.)
  removed — replaced by the BFF stub-driven Layer 3 tests.
