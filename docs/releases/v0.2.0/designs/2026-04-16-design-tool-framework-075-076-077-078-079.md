# 2026-04-16 — Design: Tool Framework + Tools Bundle (WU-075 + WU-076 + WU-077 + WU-078 + WU-079)

> [!NOTE]
> Historical terminology: this artifact uses the former `BFF` name. The live architecture renamed that component to the `runtime server` in ADR-0016 (`docs/adr/0016-runtime-server-and-client-surfaces.md`); live source now uses `internal/runtime` and the `runtime` config namespace.

## Scope

This bundle covers the harness-side tool framework and all 13 built-in tools in `internal/harness/tools/`:

- **WU-075** — Tool framework and permission model (`framework.go`, `permission.go`): executor interface, registry, permission enforcer with three levels, risk mapping, dangerous command detection, result formatting.
- **WU-076** — Read tools (`read.go`): text, PDF, DOCX, image, spreadsheet reading with file type auto-detection.
- **WU-077** — Write and Edit tools (`write.go`, `edit.go`): file creation/overwrite with snapshots, exact-match editing with uniqueness check.
- **WU-078** — Bash and Git tools (`bash.go`, `git.go`): command execution with stdout/stderr capture, read vs. mutation classification, dangerous command detection.
- **WU-079** — Glob, Grep, WebSearch, WebFetch tools (`glob.go`, `grep.go`, `websearch.go`, `webfetch.go`): file search, content search, web search API, URL fetching with HTML-to-text.

**Out of scope:** Protocol client (WU-073), MCP tool discovery (WU-081), file context management (WU-082), plan mode interception (WU-080).

## Bundle Rationale

All five WUs share the `internal/harness/tools/` package. WU-075 defines the `Tool` interface, registry, and permission model that WU-076–079 implement. Every tool depends on the framework's executor interface and permission checks. Designing them together ensures consistent tool signatures, permission behavior, and result formatting.

### D2. Tool interface and registry (WU-075)

#### D2.1. Tool interface

```go
// Tool defines a single executable tool that the model can invoke.
type Tool interface {
    // Name returns the tool's canonical name (e.g., "Read", "Bash").
    Name() string

    // Description returns a human-readable description for the tool catalog.
    Description() string

    // InputSchema returns the JSON Schema for the tool's input parameters.
    InputSchema() json.RawMessage

    // OutputEnvelope returns the output type: "text", "json", "binary", "image".
    OutputEnvelope() string

    // RiskLevel returns the tool's risk classification.
    RiskLevel() RiskLevel

    // Execute runs the tool with the given input parameters.
    // ctx carries cancellation; input is the raw JSON params from the model.
    Execute(ctx context.Context, input json.RawMessage) (*ToolExecResult, error)
}

type RiskLevel string

const (
    RiskReadOnly    RiskLevel = "read_only"
    RiskWrite       RiskLevel = "write"
    RiskExecute     RiskLevel = "execute"
    RiskDestructive RiskLevel = "destructive"
)
```

#### D2.2. Registry

```go
// Registry holds all available tools (built-in + MCP).
type Registry struct {
    mu    sync.RWMutex
    tools map[string]Tool // keyed by name
}

func NewRegistry() *Registry

// Register adds a tool. Panics on duplicate name.
func (r *Registry) Register(t Tool)

// Get returns a tool by name, or nil if not found.
func (r *Registry) Get(name string) Tool

// All returns all registered tools as protocol.ToolDefinition slice
// (for capabilities.register). Converts Tool.RiskLevel() (typed RiskLevel)
// to wire-form string via string(tool.RiskLevel()). Since RiskLevel is
// `type RiskLevel string`, the conversion is zero-cost.
// Tests assert every built-in tool's RiskLevel matches one of the four
// wire-legal strings ("read_only", "write", "execute", "destructive").
func (r *Registry) All() []protocol.ToolDefinition

// RegisterBuiltins registers all 13 built-in tools.
func (r *Registry) RegisterBuiltins(opts BuiltinOptions)

type BuiltinOptions struct {
    ProjectRoot  string // working directory for file operations
    SearchAPIKey string // Brave/SerpAPI key for WebSearch
    SearchEngine string // "brave" or "serpapi"
}
```

#### D2.3. Executor

```go
// Executor orchestrates tool execution: permission check → execute → format result.
type Executor struct {
    registry    *Registry
    permissions *PermissionEnforcer
    tracker     *FileTracker
}

func NewExecutor(registry *Registry, permissions *PermissionEnforcer) *Executor

// Execute runs a tool by name with the given input. Handles permission
// checks, dangerous command detection, and result formatting.
// Returns a ToolExecResult ready for protocol.ToolResult conversion.
//
// ToolCallID flow (resolves B2): the caller (harness event handler) receives
// a tool.call event from the BFF containing tool_call_id, tool name, and input.
// The caller passes name+input to Execute(), gets back ToolExecResult, then
// calls result.ToProtocol(toolCallID) with the original tool_call_id from the
// event. The executor does not need to know the tool_call_id — it only runs
// the tool. The correlation is maintained by the caller.
func (e *Executor) Execute(ctx context.Context, name string, input json.RawMessage) (*ToolExecResult, error)
```

Execute flow:
1. Look up tool in registry → `ToolNotFound` error if missing
2. Check permissions via `PermissionEnforcer.Check(tool, input)`
   - If denied → return result with `Status: "rejected"`, `Reason: "permission denied"`
   - If needs prompt → return `PermissionPromptResult` (caller shows UI prompt)
3. For Bash/Git tools: check dangerous command patterns
   - If dangerous → always require prompt regardless of permission level
4. Execute tool
5. Format result as `ToolExecResult`

**Input-dependent risk (Git and Bash):** These tools have a fixed `RiskLevel()` for registration (`execute` for Bash, `execute` for Git) but actual risk varies per invocation. The `PermissionEnforcer.Check(tool, input)` method inspects the input JSON for these tools specifically:
- Git: parses the subcommand to classify as read (`status`, `log`, `diff`) vs. mutation (`commit`, `push`) vs. dangerous (`push --force`, `reset --hard`)
- Bash: runs `IsDangerous(command)` on the command string

This is a documented special case — the server's tool catalog reports the registration-time risk level, but the harness enforces input-dependent risk at execution time. Per FEAT-0009: "permissions are enforced entirely in the harness."

#### D2.4. ToolExecResult

```go
// ToolExecResult is the outcome of a tool execution.
type ToolExecResult struct {
    Status     string // "success", "rejected", "error"
    Output     string
    OutputType string // "text", "json", "binary", "image"
    Error      string // populated when Status == "error"
    Reason     string // populated when Status == "rejected"
}

// ToProtocol converts to protocol.ToolResult for wire transmission.
func (r *ToolExecResult) ToProtocol(toolCallID string) protocol.ToolResult
```

### D3. Permission model (WU-075)

#### D3.1. PermissionEnforcer

```go
// PermissionLevel controls automatic tool approval.
type PermissionLevel int

const (
    // PermDefault: read-only auto-allowed, all others prompt on first use.
    PermDefault PermissionLevel = iota

    // PermAcceptEdits: read-only and file write/edit auto-allowed,
    // bash/git mutations and web tools still prompt.
    PermAcceptEdits

    // PermAutonomous: all tools auto-allowed except dangerous commands
    // (which always prompt regardless of level).
    PermAutonomous
)

// PermissionEnforcer decides whether a tool execution requires user approval.
type PermissionEnforcer struct {
    level     PermissionLevel
    
    // Per-tool approval memory (for first-use prompts in Default mode)
    mu        sync.Mutex
    approved  map[string]bool    // tool name → approved for this session
    
    // Per-domain approval (for WebFetch/WebSearch)
    domains   map[string]bool    // domain → approved
}

func NewPermissionEnforcer(level PermissionLevel) *PermissionEnforcer

// Check determines if a tool execution is allowed, needs a prompt,
// or is denied.
func (p *PermissionEnforcer) Check(tool Tool, input json.RawMessage) PermissionDecision

type PermissionDecision int

const (
    PermAllow   PermissionDecision = iota // execute without prompting
    PermPrompt                             // show permission prompt to user
    PermDeny                               // always denied (absolute deny-list)
)

// Approve records that the user approved a tool (for session memory).
func (p *PermissionEnforcer) Approve(toolName string)

// ApproveDomain records that the user approved a web domain.
func (p *PermissionEnforcer) ApproveDomain(domain string)
```

#### D3.2. Permission decision matrix

| Tool | Risk Level | Default | Accept-Edits | Autonomous |
|------|-----------|---------|--------------|------------|
| Read | read_only | Allow | Allow | Allow |
| Glob | read_only | Allow | Allow | Allow |
| Grep | read_only | Allow | Allow | Allow |
| Git (read) | read_only | Allow | Allow | Allow |
| Write | write | Prompt | Allow | Allow |
| Edit | write | Prompt | Allow | Allow |
| Git (mutation) | execute | Prompt | Prompt | Allow |
| Bash (safe) | execute | Prompt | Prompt | Allow |
| Bash (dangerous) | destructive | Prompt | Prompt | Prompt |
| Git (dangerous) | destructive | Prompt | Prompt | Prompt |
| WebSearch | execute | Prompt | Prompt | Allow |
| WebFetch | execute | Prompt/domain | Prompt/domain | Allow |

"Prompt" in Default mode means first-use per tool per session. Once approved, subsequent uses of the same tool are auto-allowed (except dangerous commands and new domains).

#### D3.3. Absolute deny-list

Even in Autonomous mode, certain patterns are always prompted:

```go
// alwaysPrompt returns true for operations that should never be auto-approved.
func alwaysPrompt(tool Tool, input json.RawMessage) bool
```

This covers: dangerous bash commands, dangerous git operations, and WebFetch to internal/private addresses (SSRF prevention — see WU-094 security review).

### D4. Dangerous command detection (WU-075)

```go
// IsDangerous checks if a command string matches known dangerous patterns.
func IsDangerous(command string) bool

// DangerousPatterns lists the patterns that trigger mandatory prompting.
var DangerousPatterns = []DangerousPattern{
    // Destructive file operations
    {Pattern: `rm\s+(-[a-zA-Z]*r[a-zA-Z]*f|(-[a-zA-Z]*f[a-zA-Z]*r))\b`, Desc: "recursive force delete"},
    {Pattern: `rm\s+-rf\s+/`, Desc: "recursive force delete from root"},
    {Pattern: `>\s*/dev/`, Desc: "redirect to device"},
    
    // Git force operations
    {Pattern: `git\s+push\s+.*--force\b`, Desc: "force push"},
    {Pattern: `git\s+push\s+.*-f\b`, Desc: "force push (short flag)"},
    {Pattern: `git\s+reset\s+--hard\b`, Desc: "hard reset"},
    {Pattern: `git\s+clean\s+.*-f`, Desc: "force clean"},
    {Pattern: `git\s+checkout\s+.*--\s+\.`, Desc: "discard all changes"},
    {Pattern: `git\s+branch\s+.*-D\b`, Desc: "force delete branch"},
    
    // System commands
    {Pattern: `chmod\s+.*777\b`, Desc: "world-writable permissions"},
    {Pattern: `chown\s+-R\b`, Desc: "recursive ownership change"},
    {Pattern: `mkfs\b`, Desc: "format filesystem"},
    {Pattern: `dd\s+`, Desc: "disk/device write"},
    
    // Network/exfiltration
    {Pattern: `curl\s+.*-d\b`, Desc: "curl with data (POST)"},
    {Pattern: `wget\b`, Desc: "download"},
    
    // Environment manipulation
    {Pattern: `export\s+LD_PRELOAD`, Desc: "LD_PRELOAD injection"},
    {Pattern: `export\s+PATH=`, Desc: "PATH modification"},
}

type DangerousPattern struct {
    Pattern string // compiled regex
    Desc    string
}
```

### D6. Read tool (WU-076)

```go
// ReadTool reads files with automatic format detection.
type ReadTool struct {
    projectRoot string
    tracker     *FileTracker
}

// Input schema:
// {
//   "type": "object",
//   "properties": {
//     "file_path": {"type": "string", "description": "Absolute path to file"},
//     "offset": {"type": "integer", "description": "Line number to start from (optional, text only)"},
//     "limit": {"type": "integer", "description": "Max lines to read (optional, text only)"},
//     "pages": {"type": "string", "description": "Page range for PDF files (e.g., '1-5', '3', '10-20'). Required for PDFs over 10 pages. Max 20 pages per request."}
//   },
//   "required": ["file_path"]
// }
```

#### D6.1. Format detection

```go
type FileFormat int

const (
    FormatText        FileFormat = iota
    FormatPDF
    FormatDOCX
    FormatImage
    FormatSpreadsheet
    FormatCSV
)

// detectFormat determines file format by extension first, then magic bytes.
func detectFormat(path string) (FileFormat, error)
```

Extension mapping:
- `.pdf` → FormatPDF
- `.docx` → FormatDOCX
- `.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`, `.bmp`, `.svg` → FormatImage
- `.xlsx`, `.xls` → FormatSpreadsheet
- `.csv` → FormatCSV
- Everything else → FormatText

Magic bytes fallback (when extension is ambiguous or missing):
- `%PDF` → FormatPDF
- `PK\x03\x04` + contains `word/document.xml` → FormatDOCX
- `PK\x03\x04` + contains `xl/` → FormatSpreadsheet
- PNG/JPEG/GIF headers → FormatImage

#### D6.2. Format-specific readers

```go
// readText reads a text file with line numbering.
func readText(path string, offset, limit int) (string, error)

// readPDF extracts text from a PDF file.
// If pages parameter is set, reads only that range. For PDFs over 10 pages
// without a pages parameter, returns an error requesting a page range.
func readPDF(path string, pages string) (string, error)

// readDOCX extracts text from a DOCX file.
func readDOCX(path string) (string, error)

// readImage returns base64-encoded image with MIME type.
func readImage(path string) (content string, contentType string, err error)

// readSpreadsheet reads XLSX/XLS as a text table.
func readSpreadsheet(path string) (string, error)

// readCSV reads a CSV file as a text table.
func readCSV(path string) (string, error)
```

Text output format (line-numbered):
```
1	first line
2	second line
3	third line
```

Image output: base64-encoded data with content type set to MIME type (e.g., `image/png`). OutputEnvelope is `"image"` for images, `"text"` for everything else.

**Vision capability gating:** before returning base64 image data, the ReadTool checks whether the current model supports vision (via `capabilities` from the tool catalog or session context). If the model lacks vision capability, the tool returns a text message: `"[image omitted: model lacks vision capability]"` instead of base64 data. This matches the provider formatting design (WU-043/044) which substitutes the same message on the wire.

#### D6.3. Dependencies

- PDF: `github.com/pdfcpu/pdfcpu` (text extraction)
- DOCX: `github.com/unidoc/unioffice` (text extraction)
- Spreadsheet: `github.com/xuri/excelize/v2` (XLSX reading)
- CSV: `encoding/csv` (stdlib)
- Image: `encoding/base64` (stdlib), `net/http.DetectContentType` for MIME

### D7. Write tool (WU-077)

```go
// WriteTool creates or overwrites files with pre-write snapshot.
type WriteTool struct {
    projectRoot string
    tracker     *FileTracker
}

// Input schema:
// {
//   "type": "object",
//   "properties": {
//     "file_path": {"type": "string", "description": "Absolute path to file"},
//     "content": {"type": "string", "description": "Content to write"}
//   },
//   "required": ["file_path", "content"]
// }
```

Execute flow:
1. Resolve path (absolute, within project root)
2. If file exists: read current content as snapshot
3. Write new content via `os.WriteFile` with `0644` permissions
4. Mark file as read in tracker (so Edit can modify it later)
5. Create parent directories if needed (`os.MkdirAll`)
6. Return success with bytes written

Snapshot storage: the snapshot is returned as part of the tool output for the conversation record. No separate snapshot file is created.

### D8. Edit tool (WU-077)

```go
// EditTool modifies existing files via exact string replacement.
type EditTool struct {
    projectRoot string
    tracker     *FileTracker
}

// Input schema:
// {
//   "type": "object",
//   "properties": {
//     "file_path": {"type": "string", "description": "Absolute path to file"},
//     "old_string": {"type": "string", "description": "Exact text to replace"},
//     "new_string": {"type": "string", "description": "Replacement text"},
//     "replace_all": {"type": "boolean", "description": "Replace all occurrences (default false)"}
//   },
//   "required": ["file_path", "old_string", "new_string"]
// }
```

Execute flow:
1. Check `tracker.HasRead(path)` → error if file hasn't been read
2. Read current file content
3. Count occurrences of `old_string`
   - 0 matches → error: "old_string not found in file"
   - \>1 match and `replace_all` is false → error: "old_string is not unique (N occurrences); use replace_all or provide more context"
4. Replace (first occurrence or all)
5. Write updated content
6. Return success with diff summary

### D9. Bash tool (WU-078)

```go
// BashTool executes shell commands with output capture.
type BashTool struct {
    projectRoot string
    timeout     time.Duration // default: 120s
}

// Input schema:
// {
//   "type": "object",
//   "properties": {
//     "command": {"type": "string", "description": "Shell command to execute"},
//     "timeout": {"type": "integer", "description": "Timeout in milliseconds (optional, max 600000)"},
//     "description": {"type": "string", "description": "Description of what this command does"}
//   },
//   "required": ["command"]
// }
```

Execute flow:
1. Parse command string
2. Check dangerous patterns via `IsDangerous(command)` — if dangerous, this was already caught by the executor's permission check which forces a prompt
3. Create `exec.Command("sh", "-c", command)` with:
   - Working directory: `projectRoot`
   - Timeout context from input or default
   - Combined stdout+stderr capture
4. Run and capture output
5. If exit code != 0, return output with error status
6. Return output with success status

Output truncation: if combined output exceeds 100KB, truncate with `[output truncated, showing last 50KB]`.

### D12. Grep tool (WU-079)

```go
// GrepTool searches file contents by regex pattern.
type GrepTool struct {
    projectRoot string
}

// Input schema:
// {
//   "type": "object",
//   "properties": {
//     "pattern": {"type": "string", "description": "Regular expression pattern"},
//     "path": {"type": "string", "description": "File or directory to search (optional)"},
//     "glob": {"type": "string", "description": "Glob pattern to filter files (optional)"},
//     "output_mode": {"type": "string", "enum": ["content", "files_with_matches", "count"]},
//     "context": {"type": "integer", "description": "Lines of context around matches"},
//     "case_insensitive": {"type": "boolean", "description": "Case-insensitive search"}
//   },
//   "required": ["pattern"]
// }
```

Implementation: pure Go using `regexp` package + `filepath.WalkDir`. For each file matching the optional glob filter:
1. Read file content
2. Apply compiled regex
3. Format output based on `output_mode`

Default `output_mode`: `"files_with_matches"`. Results limited to first 250 matches by default.

### D14. WebFetch tool (WU-079)

```go
// WebFetchTool fetches a URL and converts HTML to text.
type WebFetchTool struct {
    httpClient *http.Client
}

// Input schema:
// {
//   "type": "object",
//   "properties": {
//     "url": {"type": "string", "description": "URL to fetch"},
//     "headers": {"type": "object", "description": "Optional HTTP headers"}
//   },
//   "required": ["url"]
// }
```

Execute flow:
1. Parse URL
2. **SSRF check**: reject `file://`, `ftp://`, `localhost`, `127.0.0.1`, `::1`, RFC1918 addresses (`10.*`, `172.16-31.*`, `192.168.*`), link-local (`169.254.*`)
3. `http.Get` with 30s timeout
4. If content type is HTML: extract text using a simple HTML stripper (strip tags, decode entities, collapse whitespace)
5. If content type is plain text/JSON: return as-is
6. Truncate output at 100KB
7. Return text content

```go
// isPrivateAddress checks if the URL targets a private/internal address.
func isPrivateAddress(u *url.URL) bool

// htmlToText strips HTML tags and extracts readable text.
func htmlToText(r io.Reader) (string, error)
```
