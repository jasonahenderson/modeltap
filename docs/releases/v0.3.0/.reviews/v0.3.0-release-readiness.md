## Explicit limitations

- `retry` and `continue` are intentionally conservative in v0.3.0 and reject
  unsupported checkpoint stages rather than attempting unsafe replay.
- `fork` creates a queued child/sibling run record but does not clone
  workspace or artifact state.
- Background blocked-operation inbox behavior and full background-agent
  pause/approval semantics remain deferred to later v0.3.x work.
- Server-side execution of local side effects while no harness/executor is
  connected remains out of scope for v0.3.0.

## Approval

The implementation is ready for user release validation. A separate release
close commit should finalize shipped status and tag `v0.3.0` if the user
decides to publish this release.
