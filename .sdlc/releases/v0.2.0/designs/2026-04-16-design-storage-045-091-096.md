# 2026-04-16 — Design: Storage Bundle (WU-045 + WU-091 + WU-096)

> [!NOTE]
> Historical terminology: this artifact uses the former `BFF` name. The live architecture renamed that component to the `runtime server` in ADR-0016 (`.sdlc/adr/0016-runtime-server-and-client-surfaces.md`); live source now uses `internal/runtime` and the `runtime` config namespace.

## Review Tier

**Assigned:** C (bundled)
**Basis:** On-disk schema contract (WU-045) + cross-track command-history contract (WU-091) + migration correctness from real fixtures (WU-096). All three are Tier C per track-0-shared.md. Migration correctness is a one-shot contract — if it's wrong, users' v1 databases are damaged on upgrade.
**Plan default:** C (matches)
**Escalation reason:** n/a

## Scope

Bundled design for three related WUs that all land inside `internal/storage/`:

- **WU-045** — New `sessions`, `turns`, `session_events` tables (migration v2). New Go types: `Session`, `Turn`, `SessionFilter`, `ServerSessionEvent`. Store interface extensions for session/turn CRUD.
- **WU-091** — New `command_history` table + `history.append` / `history.list` protocol handlers (handler stub added here; wired to session lifecycle in WU-050/051). Migration v2 addendum.
- **WU-096** — Real v1→v2 upgrade tests with fixture v1 databases (empty, typical, heavy, partial-migration crash).

**Out of scope (deferred):**
- `internal/bff/session.go` session manager (WU-050)
- Conversation state reconstruction (WU-051)
- Command history protocol wiring beyond thin handler (WU-050 adds the `turn.submit` hook)
- Session-level access control / auth (FEAT-0010)
- Rest of the bff tree

## Bundle rationale

All three WUs touch the same SQLite database and share a migration version. Designing them together lets us:
- Land all schema changes in a single `PRAGMA user_version=2` step rather than two stepwise migrations that downstream work couldn't reason about.
- Commit the migration test fixtures once with the final v2 schema, rather than updating fixtures as WU-091 lands after WU-045.
- Catch cross-table FK decisions (e.g., `turns.session_id → sessions.id`, `command_history.session_id → sessions.id`) upfront.

## Design Decisions

### D1. Migration versioning via `PRAGMA user_version`

SQLite's built-in `user_version` pragma is the canonical place to record migration state. Current v1 DBs have `user_version = 0` (default — migrations never set it). This bundle introduces:

- **v0 (implicit):** fresh DB; no tables.
- **v1 (retrofit):** the existing shipped schema (`requests`, `hourly_usage`, `daily_usage`). Existing DBs in the wild are at this level but have `user_version = 0` because the migration code never bumped it. The migrate function treats `user_version = 0` with `requests` table present as v1.
- **v2 (new):** adds `sessions`, `turns`, `session_events`, `command_history` tables. Bumps `user_version = 2`.

**Migration code shape:**

```go
func (s *SQLiteStore) migrate() error {
    version, err := s.currentSchemaVersion()
    if err != nil { return err }

    if version < 1 {
        if err := s.migrateToV1(); err != nil { return err }
    }
    if version < 2 {
        if err := s.migrateToV2(); err != nil { return err }
    }
    return nil
}

func (s *SQLiteStore) currentSchemaVersion() (int, error)
func (s *SQLiteStore) migrateToV1() error
func (s *SQLiteStore) migrateToV2() error
```

**Transaction discipline — important correctness distinction:**

- `migrateToV1` is **idempotent via `CREATE TABLE IF NOT EXISTS`**, not transactional. The `partial_v1.db` fixture case (some v1 tables present, some missing) is handled by this idempotence: every `CREATE TABLE IF NOT EXISTS` is a no-op on existing tables and creates the missing ones. The final `PRAGMA user_version = 1` statement runs after all CREATE statements. Crash between CREATE statements leaves the DB partially-schemaed but re-entrant — next startup runs `migrateToV1` again and completes the missing tables. This matches the existing v0.1.x shipped migration code; WU-045 does not change this behavior.
- `migrateToV2` is **transactional**: wrapped in a `BEGIN; ...; PRAGMA user_version = 2; COMMIT;` block. A crash inside `migrateToV2` rolls back all new tables atomically; next startup sees `user_version = 1` and retries the full v2 migration from scratch. This is the contract tested by `TestMigration_InterruptedMidV2`.

The asymmetry is intentional: v1 retrofit must tolerate the existing wild DBs that have been through an arbitrary amount of crash-and-retry over their lifetime (CREATE IF NOT EXISTS makes that safe). v2 is a fresh contract that can afford full transactional all-or-nothing because no wild DBs are at v2 yet.

**Downgrade guard:** `NewSQLiteStore` rejects DBs whose `user_version` is **higher** than the binary's max known version. An older modeltap binary opening a newer DB gets a clear error instead of silently operating on incompatible schema.

```go
const MaxKnownSchemaVersion = 2

if version > MaxKnownSchemaVersion {
    return nil, fmt.Errorf("storage: database schema version %d is newer than this binary supports (max %d); upgrade modeltap", version, MaxKnownSchemaVersion)
}
```

Downgrade check runs **before** any `migrateToVN` call — otherwise we'd downgrade a newer DB by running v1/v2 migrations on it.

### D2. New tables (migration v2)

#### `sessions`

Full field list per track-0-shared.md WU-045 spec (lines 113-131):

```sql
CREATE TABLE sessions (
    id                   TEXT PRIMARY KEY,                   -- session UUID
    user_id              TEXT NOT NULL DEFAULT '',           -- FEAT-0010 owner
    project              TEXT NOT NULL DEFAULT '',           -- project root / identifier
    summary              TEXT NOT NULL DEFAULT '',           -- auto-generated short title
    active_model         TEXT NOT NULL DEFAULT '',           -- currently selected model
    model_override       TEXT,                               -- NULLABLE, session-level override
    routing_overrides    TEXT NOT NULL DEFAULT '{}',         -- JSON; empty object if none
    pinned_items         TEXT NOT NULL DEFAULT '[]',         -- JSON array
    compaction_state     TEXT NOT NULL DEFAULT '{}',         -- JSON object (buckets, thresholds hit, etc.)
    total_cost           REAL NOT NULL DEFAULT 0.0,
    total_input_tokens   INTEGER NOT NULL DEFAULT 0,
    total_output_tokens  INTEGER NOT NULL DEFAULT 0,
    context_pct          REAL NOT NULL DEFAULT 0.0,          -- last observed ratio
    status               TEXT NOT NULL DEFAULT 'active',     -- active | suspended | completed
    lock_owner           TEXT,                               -- NULLABLE, harness holding lock
    lock_expires_at      TEXT,                               -- NULLABLE, ISO8601 UTC
    created_at           TEXT NOT NULL,                      -- ISO8601 UTC
    updated_at           TEXT NOT NULL                       -- ISO8601 UTC
);

CREATE INDEX idx_sessions_user_id     ON sessions(user_id);
CREATE INDEX idx_sessions_user_active ON sessions(user_id, updated_at DESC);
CREATE INDEX idx_sessions_project     ON sessions(user_id, project);
CREATE INDEX idx_sessions_status      ON sessions(status);
```

Timestamps stored as ISO8601 TEXT (matches the existing `requests.timestamp` convention — don't mix TIMESTAMP and TEXT storage classes in the same DB). All timestamps are UTC.

Nullable columns (`model_override`, `lock_owner`, `lock_expires_at`) use SQL NULL, not empty string. Go-side: `*string` where presence matters, handled at Scan/Insert boundaries.

#### `turns`

Per track-0-shared.md WU-045 spec (lines 133-152):

```sql
CREATE TABLE turns (
    id                  TEXT PRIMARY KEY,                    -- turn UUID
    session_id          TEXT NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
    sequence            INTEGER NOT NULL,                    -- turn order within session
    role                TEXT NOT NULL,                       -- user | assistant
    content             TEXT NOT NULL DEFAULT '',            -- canonical message JSON (stringified)
    model               TEXT NOT NULL DEFAULT '',
    provider            TEXT NOT NULL DEFAULT '',
    input_tokens        INTEGER NOT NULL DEFAULT 0,
    output_tokens       INTEGER NOT NULL DEFAULT 0,
    cost                REAL NOT NULL DEFAULT 0.0,
    latency_ms          INTEGER NOT NULL DEFAULT 0,
    tool_calls          TEXT NOT NULL DEFAULT '[]',          -- JSON array
    files_touched       TEXT NOT NULL DEFAULT '[]',          -- JSON array of paths
    files_modified      TEXT NOT NULL DEFAULT '[]',          -- JSON array of paths
    compacted           INTEGER NOT NULL DEFAULT 0,          -- 0/1 bool
    compacted_summary   TEXT NOT NULL DEFAULT '',
    original_turns      TEXT NOT NULL DEFAULT '[]',          -- JSON array of ints (collapsed turn sequences)
    created_at          TEXT NOT NULL
);

CREATE INDEX idx_turns_session_id  ON turns(session_id);
CREATE INDEX idx_turns_session_seq ON turns(session_id, sequence);
```

`UNIQUE(session_id, sequence)` is tempting but rejected: compacted turns store multiple sequence numbers in `original_turns` JSON, and the `sequence` column on a compacted row reflects where the collapsed block *starts*. Uniqueness would forbid two compaction passes in the same session. The session manager enforces sequence monotonicity at the application layer.

Foreign key: `session_id REFERENCES sessions(id) ON DELETE CASCADE`. Enables `DELETE FROM sessions WHERE ...` to cascade.

**Foreign-keys pragma correctness (per-connection):** SQLite's `PRAGMA foreign_keys` is **per-connection**, not per-database. Go's `database/sql` pool dials multiple connections; setting the pragma once on `sql.DB.Exec` only affects the single connection that runs the statement. Fresh pool connections default back to OFF, silently breaking CASCADE on those connections.

The correct approach for `modernc.org/sqlite` is the DSN `_pragma` query parameter, which the driver applies to every new connection:

```go
// In NewSQLiteStore — amend the existing sql.Open call:
dsn := dbPath + "?_pragma=foreign_keys(1)&_pragma=journal_mode(WAL)"
db, err := sql.Open("sqlite", dsn)
```

(Matches the `modernc.org/sqlite` documented DSN syntax.) For `":memory:"`, use `":memory:?_pragma=foreign_keys(1)&_pragma=journal_mode(WAL)"`.

This also replaces the explicit post-open `enableWAL()` call with DSN pragma handling. The existing `enableWAL` function can remain for `PRAGMA journal_mode` verification (read-only check after open), or be removed if the DSN approach is sufficient.

A new test `TestForeignKeys_OnOnAllPoolConnections` opens a DB, forces multiple pool connections (via `db.SetMaxOpenConns(N)` + parallel queries), and asserts each reports `foreign_keys = 1`.

#### `session_events`

Per track-0-shared.md WU-045 spec (lines 156-164):

```sql
CREATE TABLE session_events (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id TEXT NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
    type       TEXT NOT NULL,                                -- auto_compact | server_restart | ...
    detail     TEXT NOT NULL DEFAULT '',
    payload    TEXT NOT NULL DEFAULT '{}',                   -- JSON object (see payload schema below)
    at         TEXT NOT NULL
);

CREATE INDEX idx_session_events_session_id ON session_events(session_id, at);
```

**Payload schema by event `type` (canonical, for WU-050 converter to `protocol.ServerSessionEvent`):**

| `type` value | Required payload keys | Optional keys | Mapping to `protocol.ServerSessionEvent` |
|--------------|-----------------------|---------------|------------------------------------------|
| `auto_compact` | `freed_tokens (int)` | `categories_summary (string)` | Populates `protocol.ServerSessionEvent.freed_tokens` from the `freed_tokens` key; `detail` is the human-readable narrative. |
| `server_restart` | none | `reason (string)`, `restart_at (ISO8601)` | `freed_tokens` is omitted on the wire (the protocol type has `freed_tokens` as optional). `detail` describes the restart. |
| `manual_compact` | `freed_tokens (int)`, `user_id (string)` | `categories_applied ([]string)` | Same as `auto_compact`. |

The WU-050 converter function:

```go
func sessionEventToProtocol(e *ServerSessionEvent) protocol.ServerSessionEvent {
    var payload struct {
        FreedTokens int `json:"freed_tokens"`
    }
    _ = json.Unmarshal(e.Payload, &payload) // best-effort; missing keys produce zero-value
    p := protocol.ServerSessionEvent{
        Type: e.Type, At: e.At.Format(time.RFC3339), Detail: e.Detail,
    }
    if payload.FreedTokens > 0 {
        p.FreedTokens = payload.FreedTokens
    }
    return p
}
```

Cross-bundle note: this schema is coordinated with the protocol-types bundle (WU-040/041/093) `protocol.ServerSessionEvent` shape. If a future event type adds a new structured field (beyond `freed_tokens`), both bundles amend in lockstep: storage payload schema table here, protocol type there, fixture coverage on both sides.

#### Multi-model branch state — explicit decision

`session.sync` (protocol WU-041) returns multi-model reviewer state (model, status, tokens, branch_id) after reconnection. That state needs a home; there are three options:

1. **No storage; in-memory only.** Server restart loses branch state; reconnecting harness gets a terminal `turn.complete` with `cancelled: true` for any mid-flight multi-model turn.
2. **Dedicated `session_branches` table.** Columns: `(session_id, turn_id, branch_id, model, provider, status, tokens, branch_started_at, branch_completed_at, error)`. Updated as branch events fire.
3. **Serialized into `sessions.compaction_state`-style JSON** on the current active turn.

**Decision (option 1):** branch state is in-memory only for v0.2.0. Rationale:
- The product already accepts that cross-reconnect token replay is not guaranteed (FEAT-0008 §"In-Flight Turn Recovery" line 469: `token_replay_available: false`).
- A BFF restart during an in-flight multi-model turn is a low-probability event and already triggers a server-restart server_event; recovering the branch state would require also recovering the actual provider HTTP streams, which we explicitly don't.
- Persisting branch state adds a new table and write path on every `token.delta` event — a cost we don't want in the streaming hot path.
- If the need arises (field data shows frequent BFF restarts during multi-model turns), a `session_branches` table can be added in a future v3 migration without breaking v2 consumers. The `session.sync` response already has `multi_model: null` for single-model turns, so adding persisted multi-model state is a backward-compatible addition.

WU-060 (multi-model branching) implements the in-memory branch tracker; `session.sync` on a restart returns `multi_model: null` with `active_turn.status: "cancelled"` and `active_turn.summary: "BFF restart; multi-model turn cancelled"`.

Documented in the Risks section below as an accepted trade-off.

#### `command_history` (WU-091)

Per track-a-bff-server.md WU-091 spec (lines 225-227):

```sql
CREATE TABLE command_history (
    id         INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id    TEXT NOT NULL DEFAULT '',
    project    TEXT NOT NULL DEFAULT '',
    session_id TEXT,                                         -- NULLABLE: drafts may have no session yet
    content    TEXT NOT NULL,
    created_at TEXT NOT NULL
);

CREATE INDEX idx_command_history_user_recent ON command_history(user_id, created_at DESC);
CREATE INDEX idx_command_history_project     ON command_history(user_id, project, created_at DESC);
CREATE INDEX idx_command_history_session     ON command_history(session_id, created_at DESC);
```

`session_id` is nullable so that harness "draft" records (not yet associated with a session) can be stored. WU-091 spec says the handler is a thin pass-through used "when the harness wants to record unsent drafts."

No foreign key on `session_id` — history outlives the session it belonged to (scope rule: user scope always wins; session scope is narrowest). Deleting a session doesn't invalidate history; the session_id column becomes a stale pointer. Pruning by user/project is retention's job (FEAT-0008 configuration, out of scope here).

### D5. Lock mechanics

Session-lock acquisition uses a single SQL statement to avoid read-then-write races:

```sql
UPDATE sessions
   SET lock_owner = ?2,
       lock_expires_at = ?3,
       updated_at = ?4
 WHERE id = ?1
   AND (lock_owner IS NULL OR lock_expires_at < ?5);
```

- If `RowsAffected() == 1`: lock acquired.
- If `RowsAffected() == 0`: someone else holds it. Follow up with `SELECT lock_owner FROM sessions WHERE id = ?` to return the current owner for the `MT-CONN-008` diagnostic payload.

`?5` (the current-time parameter) enables the "stale lock" case: if the existing `lock_expires_at` is in the past (harness disconnected, grace window elapsed — per WU-048 timing), acquisition succeeds atomically.

Release:

```sql
UPDATE sessions
   SET lock_owner = NULL, lock_expires_at = NULL, updated_at = ?3
 WHERE id = ?1 AND lock_owner = ?2;
```

Force-release (admin / CLI):

```sql
UPDATE sessions
   SET lock_owner = NULL, lock_expires_at = NULL, updated_at = ?2
 WHERE id = ?1;
```

### D6. Command history scoping

`ListCommandHistory` resolves scope per WU-091 spec:

- `scope = "user"` → `WHERE user_id = ?`
- `scope = "project"` → `WHERE user_id = ? AND project = ?`
- `scope = "session"` → `WHERE session_id = ? AND user_id = ?` (user_id enforced even in session scope so cross-user leakage is impossible at the query level)

Pagination uses `created_at DESC` ordering with a `Before` cursor for the next page. Cursor serialization: ISO8601 string (so it survives JSON round-trip in `history.list` protocol payload). Opaque to the harness — the server decides the cursor format.

The `user_id` filter is applied **always**, including under session scope. If the session's `user_id` doesn't match the requester, results are empty — no error, no leakage signal.

### D7. WU-096 migration fixtures

Fixture v1 databases live under `internal/storage/testdata/migrations/v1/`:

- **`empty.db`** — v1 schema created (`requests`, `hourly_usage`, `daily_usage` tables) but zero rows. `user_version = 0` (retrofit convention).
- **`typical.db`** — ~1k captured requests across 3 providers and 5 models, with corresponding rows in `hourly_usage` and `daily_usage`. Retention pruning state mid-cycle (some old rows dropped). `user_version = 0`.
- **`heavy.db.gz`** — ~100k requests; ~5 MB compressed target. Uncompressed at test time into a tmpdir. `user_version = 0`.
- **`partial_v1.db`** — crash-mid-migration simulation: `requests` table present, `hourly_usage` and `daily_usage` tables missing. Mimics a user whose first-launch migration crashed between CREATE statements. `user_version = 0`.

**Fixture generator:** `internal/storage/testdata/migrations/gen.go` (build-tagged `//go:build migrationgen`) produces each fixture deterministically using fixed seeds for UUIDs and timestamps. Invoked via `make testdata-migrations` (Makefile target). The committed fixtures are the canonical source; the generator is the safety net for regeneration (e.g., if v1 schema needs a retroactive tweak).

### D9. Retention interaction

Existing `DeleteBefore(ctx, time.Time)` handles `requests` row pruning. New analog:

```go
DeleteSessionsBefore(ctx context.Context, before time.Time) (int64, error)
```

Deletes sessions whose `updated_at < before`, cascading to `turns` and `session_events` via FK. `command_history` is NOT cascaded — user/project scope retention is separate (future WU).

### D10. Error cases

New errors in `internal/storage/store.go`:

```go
var ErrSessionNotFound      = errors.New("storage: session not found")
var ErrSessionLockContended = errors.New("storage: session lock held by another owner")
var ErrSchemaTooNew         = errors.New("storage: database schema version is newer than this binary supports")
```

`AcquireSessionLock` does not return `ErrSessionLockContended` — it returns `(acquired bool, currentOwner string, nil)` so callers can decide rather than branching on an error. The `bool` convention avoids an error sentinel in the happy-path code.

## Risks and Open Items

- **Risk — v1 retrofit.** Existing users' DBs have `user_version = 0`. Our migrateToV1 is `CREATE TABLE IF NOT EXISTS ...; PRAGMA user_version = 1;` — idempotent on existing v1 DBs. Test coverage: `TestMigration_V1_to_V2_Typical` exercises this explicitly (fixture DB starts at user_version = 0 with v1 tables; after migrate() runs twice, user_version = 2 both times).
- **Risk — fixture drift.** Hand-authored fixture v1 DBs may drift from what current v0.1.x shipped. Mitigation: the generator (D7) is the safety net; if drift is detected the generator regenerates fixtures against the pinned v1 schema.
- **Risk — heavy fixture size in repo.** `heavy.db.gz` targets <5 MB. If it grows beyond that, consider: moving to `git-lfs` (requires infra change) or reducing the row count. Decision: hold <5 MB by row count; if needed we reduce from 100k to 50k.
- **Risk — FOREIGN KEYS pragma enforcement.** SQLite requires `PRAGMA foreign_keys = ON` per connection. If a consumer opens the DB without it, FK cascade is silently disabled. Mitigation: `NewSQLiteStore` sets it, and all consumers go through `NewSQLiteStore`. Add a test that confirms the pragma is set after open.
- **Risk — `sessions.project` naming ambiguity.** Column holds the project root path; but "project" in FEAT-0008 §"Project Context" means more than just a path (config_file, config_content). Decision: `sessions.project` stores the root-path identifier only; full project context travels via protocol on each resume and is not denormalized into storage.
- **Risk — timestamp storage as TEXT.** Existing `requests.timestamp` is TEXT. Consistent convention but means string-compare ordering; indexed queries rely on ISO8601 lexicographic ordering being correct (always true for Z-suffixed UTC). Documented in sqlite.go header comment.
- **Risk — large sessions.turns row count.** A long session may have thousands of turns. `ListTurns(sessionID)` returns all; if a harness holds a 50k-turn session, `SELECT * FROM turns WHERE session_id = ?` loads all rows. Current WU scope doesn't need streaming iteration; deferred to WU-050 / WU-064 if real-world sessions get that large.
- **Non-risk:** compaction. WU-061 owns compaction logic; storage only stores compaction state as JSON blobs on sessions.compaction_state + turn.compacted flag.

## Deviations from track-0-shared.md

- **Store interface method names.** Spec says `CreateSession`, `GetSession`, `UpdateSession`, `ListSessions`, `CreateTurn`, `GetTurn`, `ListTurns`, `GetSessionTurns`, `AppendServerEvent`, `ListServerEvents`, `DeleteSessionsBefore`. Design adds: `AcquireSessionLock`, `ReleaseSessionLock`, `ForceReleaseSessionLock`, `SessionSummaries`, `SessionFilesTouched`, `SessionFilesModified`, `AppendCommandHistory`, `ListCommandHistory`. The spec mentions "derivation helpers for session.list and session.details" without naming them; the design names them explicitly. TPM should update the spec to list the derivation helpers and the lock methods.
- **`GetSessionTurns` renamed to `ListTurns(sessionID string)`.** Design uses `ListTurns(ctx, sessionID)` (one argument) because it's the only turn-list query we need. TPM should update spec to match or note the rename.
- **`SessionFilter` has `UserID` required.** Spec doesn't say "required"; design makes it so because cross-user listing is a privacy violation (FEAT-0010). TPM should add the constraint.
- **`ServerEvent` renamed to `ServerSessionEvent` in storage.** Matches the protocol bundle rename (same reason: avoid clash with `protocol.ServerError`).
