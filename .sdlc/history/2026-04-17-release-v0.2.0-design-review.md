## Main Issues Raised

- Multi-model reconnect behavior after BFF restart regresses the accepted `session.sync` recovery contract.
- Bundle 4 defines `capabilities.request` as a re-registration path while simultaneously forbidding any second `capabilities.register` on the same connection.
- The harness protocol client expects a `capabilities.register` response shape that does not match the shared protocol contract.
- Bundle 4 introduces `MT-CONN-013`, but the shared diagnostics taxonomy still stops at `MT-CONN-012`.
- Bundle 10 adds `ParseStreamEvent` to the provider interface outside the shared provider-contract bundle, so the contract is not actually Phase-1-stable.
