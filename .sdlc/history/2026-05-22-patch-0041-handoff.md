## What PATCH-0041 Implements

PATCH-0041 wires session inspection into the production shell:

- `/sessions show [id]`
- `/sessions details [id]`
- singular aliases through `/session show [id]` and `/session details [id]`

When no id is supplied, the command uses the current active session id. If no
active session exists, it reports a status error instead of calling the runtime
with an empty session id.

The command calls:

- `session.details` for the selected session
- `run.list` with `SessionID` set to the same target session and `Limit: 10`

The output is a compact `HostInfoEvent` detail view with session metadata,
turn summaries, touched/modified files, server events, recent runs, and a
run-native drill-down hint.

## Sequencing Fix Included

The second PATCH-0041 commit fixes session-switch turn sequencing:

- `session.resume` now returns `next_sequence`
- the runtime computes it from the restored user-turn sequence
- the production host seeds its local next `turn.submit` sequence when adopting
  a resumed session
- `/clear` resets the host sequence for the newly-created session
- plain `turn.submit` acknowledgement still records the returned session id
  without resetting the sequence

This prevents resumed sessions from appearing stuck at the first persisted
turn/run because later submits would restart at sequence 1.
