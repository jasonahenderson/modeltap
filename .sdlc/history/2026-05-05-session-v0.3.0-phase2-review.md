Claude recommended opening a new session for the full implementation review,
with three reasons: (1) bias risk — having produced the Phase 2 review (F6-F15),
the same reviewer is likely to ask "are my findings addressed?" instead of
reading the code on its own merits; (2) scope — design conformance + tests +
race-safety + security + coding conventions across 6+ WUs is a session's worth
of focused work; (3) cache economics — this session has accumulated a long
context across PATCH-0016, the Phase 2 review, and chat-history updates,
making continued long replies expensive. A short handoff doc would point the
new session at the commits, designs, and Phase 2 findings to verify.

Quick spot-checks (e.g., "did F6 trace_id actually land in WU-109?") are
cheaper to run in this session because the design context is already loaded;
broader review benefits from the new session. User decision pending.
