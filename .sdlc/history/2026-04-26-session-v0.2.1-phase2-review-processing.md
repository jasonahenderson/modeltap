## Substantive design changes

These are not just edits — they are real refinements to the v0.2.1
componentization contract:

1. **Permission identity preserved across the boundary** (Codex #2 blocking).
   `Runtime.ResolvePermission` now takes `(ctx, requestID, decision)`. With
   multiple pending permissions, the host needs the request identity to
   route the decision correctly.
2. **Submission lifecycle events are explicit** (Codex #3). WU-098 now
   includes `SubmissionAcceptedEvent` and `SubmissionFailedEvent` so the
   shell can deterministically handle pending submissions, host rejection,
   and queue-release failure.
3. **Optimistic assistant-row creation documented** (Kimi #3). The shell
   appends both the user-visible row and the placeholder assistant row on
   `SubmitTurnAction`. `RunStartedEvent` does not move the row — it only
   correlates run IDs. This preserves the spike's `beginSubmission()`
   behavior.
4. **Mid-stream permission pause is adapter-driven** (Kimi #2). The host
   adapter buffers `RunDeltaEvent` forwarding while a permission is pending
   and replays buffered deltas in arrival order on resolution. This keeps
   pause/resume off the `Runtime` interface and off the shell.
5. **HostStatusEvent is structured** (Kimi #5). Adds a `StatusKind` enum so
   the shell can drive chrome behavior (pulsing dot, interrupt-armed
   styling, permission-pending highlight) without parsing display strings.
6. **`pendingSubmissions` merge buffer is a first-class shell-state concept**
   (Kimi #4). WU-098 documents it as shell-owned, WU-100 Step 5 references
   it explicitly, WU-102 verifies multi-item queue release preserves FIFO
   across the merge.
7. **Theme/style import boundary is binding** (Kimi #7). `internal/harnessshell`
   may not import `internal/harness/theme` or any modeltap-specific style
   constants. The reusable package owns its own theme-neutral styles.
8. **Definite scope rule for the reusable package** (Codex #5 / Kimi #19).
   Sidebar, command palette, agent surfaces, session/model/history catalogs,
   and orchestration UI all stay outside `internal/harnessshell`. WU-100 Step
   2's "only if" conditional is replaced with a definitive list.
9. **Test-migration contract is explicit** (Kimi #10). The spike test file
   is treated as a migration checklist, not as a continuously-passing suite,
   during cutover stages. No type aliases. New shell-package tests must
   pass before any spike test is deleted.
10. **Fake-host capability matrix** (Kimi #17 + cross-cutting). WU-102 now
    enumerates every host event the test fake must support so Layer 1 tests
    can drive every shell-visible behavior.
