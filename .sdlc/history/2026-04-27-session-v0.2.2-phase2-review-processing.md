## Major architectural decisions resolved

The Phase 2 review surfaced several architectural ambiguities the
Phase 1 design papered over. The dispositioned design now resolves
them concretely:

- **Permission gating ownership.** Phase 1 said
  `ToolDispatcher.ResolvePermission`, but no such method exists.
  The post-review architecture is unambiguous: the broker logic
  lives in `ProductionRuntime`. `ToolDispatcher` is unchanged.
  The bridge is a `sync.Map[string]chan PermissionDecision` keyed
  by `ToolCallID`, with the runtime registering a `PromptCallback`
  on `tools.PermissionEnforcer` that emits the projection-bound
  `harness.PermissionPromptMsg` and blocks on the per-call channel.

- **WU-104 scope split.** Phase 1 had one large WU-104; the
  blocking Codex finding correctly identified that WU-105 cannot
  depend on a single in-progress WU-104. The split into 104a
  (`SubmitTurn` + scaffolding), 104b (preview/permission/interrupt),
  and 104c (commands/paste-summary + MCP lazy-start) lets WU-105
  begin as soon as 104a lands.

- **`SubmitTurn` async/sync bridge.** The Phase 1 design proposed
  a sync wrapper that intercepts `TurnSubmittedMsg`. Kimi #4
  caught the double-delivery problem: the existing event bridge
  also delivers the message to `ProgramSender`, so the projection
  layer would either miss the message or see duplicates. The
  resolution is a router hook on `ConnectionManager`: the bridge
  writes to BOTH the per-correlation promise channel AND the
  sender, in a single synchronization point.

- **Interrupt RPC.** Phase 1 invented `Client.SendInterrupt` against
  a hypothetical `turn.interrupt`. Codex correctly pointed out that
  `Client.CancelTurn` against `protocol.MethodTurnCancel` already
  exists. WU-104b uses it; the not-supported fallback synthesizes
  `RunStoppedEvent` (per Kimi #7) so the UX preserves clean stop
  semantics.

- **`LoadPreview` path resolution.** Phase 1 left
  `PreviewRequest.Path` undefined for composer tokens. The
  resolution is an adapter-side `tokenAttachments` map populated on
  every `dispatchSubmit` (and on composer-token state injection).
  `dispatchLoadPreview` looks up the table to populate the path
  before calling `Runtime.LoadPreview`.

- **`ViewportState` cache.** The Phase 1 design's "lazy allocation
  in View" doesn't survive value-receiver semantics. The cache
  pointer is now preallocated in `New()`; `View()` mutates the
  pointed-to value (which works through value receivers because
  `*ViewportState` is a pointer field).

- **Bare `modeltap` behavior.** Codex flagged the proposed
  bare-launch change as advisory; the disposition is to **reject**
  it. v0.2.1 deliberately stripped bare-launch when the broken
  legacy harness was scrapped. Restoring it now would surprise
  users with an auto-BFF-start path that hasn't been exercised in
  v0.2.2 yet. Future release decides if/when to bring it back.
