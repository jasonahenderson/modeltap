## HIL findings

### HIL-001: `internal/harnessspike` end-state is redundant with `internal/harnessdemo`

The current Phase 2 designs gave `internal/harnessspike` two end-state roles:

1. WU-100 Stage E: a thin Bubble Tea wrapper around `internal/harnessshell`
   plus a fake/demo host adapter — i.e., a CLI demo program
2. WU-102 Layer 3: a small home for cutover-only compatibility tests

But WU-099 already proposed `internal/harnessdemo` as the canonical fake/demo
runtime package. So the design ended with two demo packages doing
overlapping work, and "spike" vocabulary that is stale once the spike is
over.

**Disposition:** accepted. v0.2.1 will delete `internal/harnessspike`
entirely. The package's end-state responsibilities split:

- canonical shell logic → `internal/harnessshell`
- fake/demo runtime → `internal/harnessdemo`
- Layer 3 cutover tests → `internal/harnesshost` integration tests
- demo CLI entrypoint → renamed/replaced (Phase 3 implementation detail)

## What changed in the design

After this HIL pass the v0.2.1 end state is genuinely a clean cut:

- `internal/harnessshell` — reusable conversation-shell component
- `internal/harnesshost` — modeltap-specific host adapter
- `internal/harnessdemo` — fake/demo runtime for examples and test fixtures
- demo CLI entrypoint — name TBD; imports `harnessshell` + `harnessdemo`
  directly
- no package called "harnessspike" survives the release

WU-100's Stage E is now "Spike package deletion," not "Spike de-thickening."
WU-102's Layer 3 lives in `internal/harnesshost/integration_test.go` (and
optionally `internal/harnessdemo/demo_test.go`) rather than in the deleted
spike test file. WU-099's "three valid hosts" is reduced to two host
packages plus pure test fakes.
