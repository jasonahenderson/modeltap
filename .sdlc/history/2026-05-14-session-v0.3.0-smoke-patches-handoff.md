## What still needs to ship in v0.3.0

### PATCH-0039 — `/sessions delete <id>` and `/sessions prune`

Doc not yet written. Scope:

- **Storage** (`internal/storage/sessions.go`):
  - `DeleteSession(ctx, userID, project, sessionID) error` — single delete with access check; cascades turns + events via existing FK
  - `DeleteEmptySessions(ctx, userID, project) (int64, error)` — bulk delete where no turns exist; returns count

- **Protocol** (`internal/protocol/messages.go`, `internal/protocol/sessions.go`):
  - `MethodSessionDelete = "session.delete"`, `MethodSessionPrune = "session.prune"`
  - `SessionDelete{SessionID}` / `SessionDeleteResponse{Deleted bool}`
  - `SessionPrune{}` / `SessionPruneResponse{Deleted int}`

- **BFF** (`internal/bff/session.go`):
  - `handleSessionDelete` — verify access via `verifySessionAccess`, refuse if the session has a non-empty unexpired `lock_owner`, call `store.DeleteSession`
  - `handleSessionPrune` — call `store.DeleteEmptySessions`, return count
  - Register both in `SessionManager.Register`

- **Harness** (`internal/harnesshost/production_runtime.go`):
  - Add `case "delete":` and `case "prune":` in `handleSessionCommand` (which I already restructured in PATCH-0038 — the `if args == "" || args == "list"` short-circuit only catches list)
  - `handleSessionDelete(ctx, id)`, `handleSessionPrune(ctx)`
  - Refuse `delete` of the currently-active session (user must `/clear` first)
  - Update `helpText` to include `delete <id>` and `prune` in the `/sessions` line

- **Tests**:
  - Storage: cascade and access-denial; prune leaves non-empty alone
  - BFF: delete refuses locked session
  - Harness: delete and prune handler emit expected status

Sized at ~250 LOC + tests. Should be one commit.

## Architecture decisions made in this session

1. **Session semantic — Option A (Claude-aligned).** `/clear` = new conversation (new session_id). Old cosmetic `/clear` removed. Shell auto-resumes most-recent on launch. Welcome message hints `/clear for new conversation`. Decision captured in PATCH-0038 doc.

2. **Don't restart from the spike.** User asked early in the session whether to discard the BFF and rebuild from the harness spike. I reviewed the spike (deleted in WU-100, commit `8f2d392`) and confirmed it had no BFF wiring — 2027 lines of standalone Bubble Tea UI with fake streaming. The actual hard work (storage, providers, session lifecycle) was always in the BFF. The smoke-test findings clustered as "production wiring forgotten" and "contract drift between components" — not architecture rot. Bug-fix rate was *decreasing*, which is the opposite signal of foundation problems. Recommended fix-forward; the user agreed. See the original analysis in this session's transcript before the patch sweep started.

3. **F17 split — placeholder now, proper later.** v0.3.0 ships with elapsed-seconds added to the existing flat status string (PATCH-0035, ~50 LOC). The structured `StreamingStatus` surface with verb / stage / running tokens / active tool — the part that matches what Claude Code / OpenCode / Codex show — is FEAT-0024 for v0.3.1.

4. **PATCH-0038 / PATCH-0039 split.** Original PATCH-0038 was going to be one patch covering /clear redefine + auto-resume + /sessions current + /sessions delete + /sessions prune. Split so the semantic redefine (the user-facing change) lands atomically and the cleanup tooling follows in PATCH-0039. PATCH-0038 doc lists 0039 as the follow-up.
