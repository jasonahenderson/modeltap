Quick Start

Get up and running with modeltap in a few steps:

  1. Start the proxy with a default upstream: 
    modeltap start

    This starts the proxy on port 8080 with https://api.anthropic.com as the default upstream. Specify a different upstream with:

    modeltap start --upstream https://api.openai.com
  2. Point your AI client to http://localhost:8080 instead of the provider's API URL. For example: 
    # Anthropic Python SDK
import anthropic
client = anthropic.Anthropic(base_url="http://localhost:8080")

# OpenAI Python SDK
from openai import OpenAI
client = OpenAI(base_url="http://localhost:8080/v1")
  3. View captured logs: 
    modeltap logs
  4. Check proxy status: 
    modeltap status
  5. Open the web dashboard (requires --dashboard flag on start): 
    modeltap start --dashboard
modeltap dashboard

Configuration Options

The config file is stored at ~/.modeltap/config.yaml (or $XDG_CONFIG_HOME/modeltap/config.yaml when that env var is set). Installs predating PATCH-0006 still load from ~/.config/modeltap/config.yaml with a deprecation warning. If no config file exists, modeltap uses built-in defaults.

Available Settings

KeyDefaultDescription
port8080Port the proxy listens on
upstreamhttps://api.anthropic.comDefault upstream API URL
db_path~/.modeltap/modeltap.dbPath to the SQLite database
retention_days30Days to retain captured data
max_body_size10MBMaximum body size to store
dashboard.enabledfalseWhether dashboard starts with proxy
dashboard.port8081Port the dashboard listens on
dashboard.bind127.0.0.1Address the dashboard binds to

Example Config File

port: 8080
upstream: https://api.anthropic.com
db_path: ~/.modeltap/modeltap.db
retention_days: 30
max_body_size: 10MB

dashboard:
  enabled: true
  port: 8081
  bind: 127.0.0.1

providers:
  anthropic:
    upstream: https://api.anthropic.com
  openai:
    upstream: https://api.openai.com

Environment Variable Overrides

Every config key can be overridden with an environment variable using the MODELTAP_ prefix. Nested keys use underscores in place of dots.

Config KeyEnvironment Variable

Precedence order (highest to lowest): CLI flags > environment variables > config file > defaults.

Provider Support

modeltap automatically detects which AI provider a request is targeting and applies the correct parser for extracting metadata (model name, token counts, cost).

Anthropic

  • API: Messages API (/v1/messages)
  • Models: Claude model family (claude-sonnet-4-20250514, claude-haiku-4-20250414, etc.)
  • Authentication: x-api-key header
  • Streaming: SSE streams captured and reassembled (message_start, content_block_delta, message_delta events)

Anthropic is detected when the request host is api.anthropic.com, an anthropic-version header is present, or the path contains /v1/messages with an x-api-key header.

OpenAI

  • API: Chat Completions API (/v1/chat/completions)
  • Models: GPT model family (gpt-4o, gpt-4o-mini, etc.)
  • Authentication: Authorization: Bearer <key> header
  • Streaming: SSE streams captured and reassembled (chunked data with [DONE] terminator)

OpenAI is detected when the request host is api.openai.com or the path contains /v1/chat/completions (without an Anthropic-Version header).

Provider-Specific Upstream Routing

You can configure different upstream URLs for each provider in the config file:

providers:
  anthropic:
    upstream: https://api.anthropic.com
  openai:
    upstream: https://api.openai.com

modeltap routes detected traffic to the correct upstream, even though clients always send requests to the single proxy address.

Service Management

modeltap can run as a platform-native background service that starts automatically at login and restarts on crash. This is an alternative to running modeltap start in a terminal window.

Installing the Service

modeltap service install

Creates a service definition appropriate for your platform:

  • macOS: A launchd user agent plist is written to ~/Library/LaunchAgents/ and loaded immediately.
  • Linux: A systemd user service unit is written to ~/.config/systemd/user/ and enabled.

After installation, the proxy runs in the background with no terminal window required.

Checking Status

modeltap service status

Shows whether the service is installed, running, and its process ID.

Viewing Logs

# Show the last 50 lines (default)
modeltap service logs

# Show the last 200 lines
modeltap service logs --lines 200
modeltap service logs -n 200

On macOS, logs are read from ~/.modeltap/modeltap.log (or the legacy ~/.config/modeltap/modeltap.log on older installs). On Linux, logs are read from journalctl.

Removing the Service

modeltap service uninstall

Stops the running service and removes the service definition file. Your configuration and captured data are not affected.

Dashboard Usage Tips

Enabling the Dashboard

The dashboard is disabled by default. Enable it in one of three ways:

  • CLI flag: modeltap start --dashboard
  • Config file: set dashboard.enabled: true
  • Environment variable: MODELTAP_DASHBOARD_ENABLED=true

Log Viewer

  • Use the filter bar to narrow results by provider, model, status code, or time range.
  • Click any row to see the full request/response detail, including headers and body with JSON syntax highlighting.
  • Enable Auto-refresh to have the log table update automatically every 5 seconds.
  • Use the pagination controls at the bottom to navigate through large result sets.

Metrics View

  • The metrics view shows aggregated usage statistics including request counts, token usage, estimated cost, and latency.
  • Use the time range selector and group-by options to focus on specific periods or breakdowns by provider/model.

Status View

  • The status page shows current proxy configuration (port, upstream URL), database record count, and retention settings.
  • Data refreshes automatically when you navigate to the status tab.

Theme

Use the theme toggle button in the top navigation bar to switch between light and dark modes. Your preference is saved in local storage.

Time Filters

Several views accept time-based filters. Times can be specified as:

  • Duration shorthand: a number followed by a unit -- s (seconds), m (minutes), h (hours), d (days). Examples: 24h, 7d.
  • RFC3339 timestamp: a full timestamp such as 2026-03-01T00:00:00Z.
